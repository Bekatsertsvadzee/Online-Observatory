## Prioritized findings

### P1 — Payment retry race corrupts Observer Pack settlement (reproduced)

`apps/api/src/features/payments/settle.ts:78,467` and `apps/api/src/features/missions/observer-pack.ts:295`.

A callback reads its associated pack before acquiring the mission/pack locks. Meanwhile, a retry expires the hold and reuses that pack with a new paymentId. Settlement re-reads paymentId under lock but never compares it with the callback's paymentId. The old callback marks the replacement checkout PAID while its new payment remains pending. This also loses the intended unmatched-payment refund classification.

Deterministic PostgreSQL reproduction: pause the old callback just after its payment/pack lookup; buy again after hold expiry; resume the callback. Expected replacement pack PENDING_PAYMENT; actual PAID. Examine the FAILED branch for the analogous stale-association cancellation.

### P1 — Ended missions can receive newly paid observer seats (reproduced)

`apps/api/src/features/payments/settle.ts:452`.

Buy while OBSERVING, change the mission to COMPLETE, then settle the callback. The helper locks only observerCapacity and never checks mission state/join policy. Actual result: pack PAID, although joining the completed mission is refused. No CAPTURED_WITHOUT_SEAT audit classification is emitted for the refund engine. Revalidate deliverability while holding the mission lock; record captured money without awarding an unusable seat.

### P1 — A paid booking has no implemented path into an observation

`apps/api/src/features/payments/settle.ts:239`; `apps/api/src/features/missions/session.ts:104`.

Settlement creates SCHEDULED. Starting a session rejects SCHEDULED. Operator override also requires an already-live mission and a session. Source inspection found no scheduler/dispatcher that performs the initial transition and authorized GOTO. The agent can run a mission when directly supplied an appropriate command; the customer booking flow does not supply it. This is an integration gap, not a failing existing unit test.

### P1 — Client authentication is not exposed by this API build

`apps/api/src/features/auth/actions.ts:69`.

Sign-in/registration are server actions extracted from the old UI. There are no corresponding HTTP route handlers or auth endpoints in the OpenAPI spec, and the initial production build's server-action manifest has empty node/edge action maps. The separate clients cannot import these server functions over HTTP. Add the contract-owned authentication boundary and test actual cookie issuance and authenticated requests. The separate client repository was not inspected.
